# Сервис прогноза денежных потоков

Один репозиторий на всю команду. Каждый работает в своей папке и своей ветке. Сервер собирает только `main`.

| Папка | Кто | Ветка |
|---|---|---|
| `frontend/` | фронт | `frontend` |
| `gateway/` | Go, вход | `backend` |
| `ledger/` | Go, выписка | `backend` |
| `planning/` | Go, планы | `backend` |
| `forecast/` | модель и обвязка | `forecast` |
| `deploy/` | сборка на сервере | `main` |

Сайт снаружи видит только вход. Выписка, планы и прогноз друг друга не вызывают.

## Как начать

```bash
git clone https://github.com/ArtemParshyn/LaynDlyaKrutih.git
cd LaynDlyaKrutih
git checkout -b frontend
```

Имя ветки своё: `frontend`, `backend` или `forecast`.

Перед работой подтяни свежий `main` в свою ветку. Коммить только свои папки. В `main` вливай, когда код запускается.

Файл `.env` в репозиторий не коммитится. Пароль базы и ключ токена лежат только на сервере.

## Что уже есть

`forecast/` принимает пакет и отдаёт 30 дней. Нерегулярный поток пока ноль: модель подставляется в `build.irregular`. Обвязка сама складывает остаток.

На каждый день остаток считается так: вчерашний остаток плюс приход минус расход. Приход и расход — это нерегулярная часть плюс платежи из `scheduled` на эту дату. Если остаток уходит ниже нуля, в ответе появляется предупреждение с суммой нехватки.

- история короче 30 дней — в ответе `rough: true`, у предупреждения `chance: 0.5`;
- нет остатка или даты — ответ 422.
